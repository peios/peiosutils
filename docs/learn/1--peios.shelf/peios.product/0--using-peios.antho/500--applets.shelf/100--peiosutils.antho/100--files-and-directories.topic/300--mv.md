`mv` changes where a file is named. Within a filesystem that usually means a
rename; across filesystems it requires a copy followed by removal of the
source.

## Before you start

Use a terminal with Peiosutils installed. For examples that create files,
start in a disposable working directory without existing example names.

## Perform the task

Follow these steps in the same shell:

1. Create the example input:

   ```sh
   printf 'Draft\n' > draft.txt
   ```

2. Run the next command:

   ```sh
   mv -i draft.txt report.txt
   ```

3. Read the selected file contents:

   ```sh
   cat report.txt
   ```

## Check the result

`report.txt` contains `Draft`, and `draft.txt` is absent. The interactive
option asks before replacing an existing destination.

## Understand which object keeps its security

A rename keeps the same object and its security descriptor. Moving into a
different directory does not itself apply that directory's inherited rules.

A copy across filesystems creates a new object. Its default security comes
from the destination directory. The default move carries data, timestamps, and
ordinary extended attributes on a best-effort basis, not the source's complete
security identity.

Explicit attribute-selection options force copying followed by removal even
within one filesystem. Review the selected preservation components in `mv(1)`
and `cp(1)` before relying on such a move for a backup.

A successful status can include skipped destinations under an update policy.
Check the destination and source when your task requires every input to move.
