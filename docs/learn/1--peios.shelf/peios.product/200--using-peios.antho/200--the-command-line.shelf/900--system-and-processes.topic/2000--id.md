`id` displays identity information. Peios retains numeric user and group
identifiers for compatibility, while access decisions use security identifiers
and token attributes.

## Numbers are a projection

A security identifier (SID) is the identity used by the access model. Its
numeric projection does not capture every SID or token property. Some
logon-type groups deliberately have no number, and deny-only group attributes
cannot be represented by a plain group number.

Two tokens can therefore print the same numeric groups while authorizing
different operations. The default context field supplements the numeric view
with the user SID and integrity level. Use `token show --all` for a broader
token inspection.

## A process and an account are different queries

With no account argument, `id` reads the calling process's identity. With an
account name, it asks the identity service about that account. The account
query has no running token from which to read an integrity level or a
logon-specific group set.

A process can carry automatically added groups such as `Everyone` and `Local`.
Those memberships need not be stored as explicit account records. A
named-account query can therefore return a shorter group list without either
query being wrong.

## Keep inspection separate from authorization

The real and effective identity views relate to the primary and effective
identity in the Peios execution model. A utility's printed number does not
change a token or grant rights.

Compatibility output can omit the context field, including when
`POSIXLY_CORRECT` requests the compatibility shape. `id(1)` defines the
field-selection options and output conditions.
