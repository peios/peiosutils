Use `cp` to make another file or directory tree from existing data. A new
copy normally gets security from its destination directory, so copying into
a different location can change who can access it.

## Before you start

- Check that you can read the source and create files in the destination.
- Keep a separate copy of any destination data you need. Overwriting and
  failed copies do not provide rollback.
- Choose whether you need the contents alone or particular source attributes.
  Preserving an owner or access rules requires permission to set them.

## Copy a file

1. Copy the file to its new name. This example assumes `report.txt` exists:

   ```sh
   cp report.txt report-backup.txt
   ```

2. If the destination might already contain useful data, request a prompt
   before overwriting it:

   ```sh
   cp -i report.txt report-backup.txt
   ```

3. Compare the result with the source:

   ```sh
   sha256sum report.txt report-backup.txt
   ```

Check that both lines report the same digest. This checks file contents,
not access rules, timestamps, or other attributes. See `sha256sum(1)` for
its output format.

## Copy a directory tree

Use recursive copying for a directory and its contents. This example assumes
`notes` exists and `notes-copy` does not:

```sh
cp -R notes notes-copy
```

The new files inherit security at the destination. The source remains in
place. If the destination already exists as a directory, `cp` copies the
source directory into it; check the destination path before running the
command. See `cp(1)` for source and destination naming rules.

## Retain selected attributes

Preservation is a separate choice from copying contents. For example, retain
access and modification times with:

```sh
cp --preserve=timestamps report.txt report-backup.txt
```

Use `-p` when you also require executable status to be preserved. A plain
copy attempts to preserve executable status without making failure fatal;
an explicit preservation list selects only what it names.

For a directory tree, `-a` requests recursive copying, preserves symbolic
links as links, and requests all supported attributes. It can fail if you
cannot read or set the requested security information. It is not a complete
security backup: the supported descriptor selection excludes the group
component and does not promise every descriptor control bit.

To carry explicit access rules into another directory while allowing that
directory to supply inherited rules, use `--sd-explicit`. Use `--sd` to
request the source owner and full discretionary and audit access-control
lists. Neither option selects the descriptor's group. See `cp(1)` for the
full preservation contract and required access.

## Check the result

Check the command's exit status and verify the content and attributes your
task requires. A failed copy can leave a partially populated destination;
a required attribute failure can also truncate a copied file. Keep the
source and any known-good backup until verification is complete.

Extended-attribute preservation adds source attributes but does not remove
attributes found only at an existing destination. Unsupported source
attribute enumeration is accepted; failure to set an attribute that was
read is an error. These distinctions matter when copying between different
filesystems.
