`yes` writes the same line repeatedly until output fails or it is stopped. It
can provide test input for a consumer that reads a known number of records.

## Before you start

Use a terminal with Peiosutils installed. For examples that create files,
start in a disposable working directory without existing example names.

## Perform the task

Run the command:

```sh
yes sample | head -n 3
```

## Check the result

The output contains three lines of `sample`. The consumer then closes the
pipe, stopping further useful output.

## Do not automate unexplained prompts

A stream of affirmative answers can accept more than the prompt you expected.
Prefer a command's documented noninteractive option when carrying out a real
operation.

A pipeline has more than one exit status. A broken pipe in the producer can be
expected after an intentional short read, while the consumer's failure still
needs attention. Check the shell's pipeline-status behavior.

See `yes(1)` for the complete options and status contract.
